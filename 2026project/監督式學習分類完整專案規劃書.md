## 1. 專案概述與問題定義（Problem Framing & Success Criteria）

### 1.1 專案背景與目標
網路媒體與社群平台常透過誇大、製造懸念或情緒化標題（Clickbait）吸引點擊，影響資訊可信度與閱讀體驗。本專案旨在運用自然語言處理（NLP）與監督式學習，針對輸入的英文標題建立一套**可重現、具備去偏防護、低延遲且可解釋**的二元分類管線，自動辨識標題是否屬於標題黨。

### 1.2 輸入輸出與問題定義
| 項目 | 規格說明 |
| :--- | :--- |
| **任務類型** | 監督式學習 — 短文本二元分類（Binary Text Classification） |
| **輸入特徵（`headline`）** | 英文標題純文字（平均 9.07 字，範圍 1–26 字） |
| **預測目標（`clickbait`）** | `1` = 標題黨（Clickbait），`0` = 正常新聞標題（Non-Clickbait） |
| **推論輸出** | 預測類別標籤、經校準之預測機率（`predict_proba`）與風險信心分級 |

### 1.3 成功標準與評估基準
- **Baseline 基準線**：`TfidfVectorizer` + `LogisticRegression`（目標 F1-Score $\ge$ 0.90）。
- **測試集目標效能**：Accuracy $\ge$ 0.95、F1-Score $\ge$ 0.95、ROC-AUC $\ge$ 0.98、PR-AUC $\ge$ 0.98。
- **工程與去偏約束**：
  - 單筆推論延遲 $< 20\text{ ms}$。
  - 模型不可依賴大小寫格式（Title Case）或特定年代詞彙作為主要決策捷徑。

### 1.4 研究範圍與先天限制聲明（Research Limitations）
在進入建模流程前，必須明確界定本專案資料集所決定的研究邊界：
1. **無上下文與內文驗證（Context-Free）**：資料集僅含 `headline` 與 `clickbait` 兩欄，缺乏內文（Body）、發布來源（Source）、網址與真實點擊率（CTR），模型僅能辨識**表面寫作風格**，無法驗證「標題與內文是否名實不符」。
2. **來源與格式高度混雜（Source & Formatting Confounding）**：實證盤點顯示 `clickbait=1` 有 **99.4%** 為 Title Case，而 `clickbait=0` 僅 **33.5%**；且 `clickbait=1` 幾乎不含 `?`（0.3%）與 `!`（0.2%），顯示資料可能直接依媒體來源貼標，模型極易學到「排版風格」而非「標題黨語意」。
3. **時間與文化領域侷限（Temporal & Cultural Scope）**：內容高度集中於 **2005–2016 年**歐美英語流行文化與新聞（`2015` 年出現 506 次、`2016` 年 176 次），不具備直接跨語言（如繁體中文）或跨時代（2020 年代網路迷因／短影音標題）的泛化能力。
4. **二元標籤簡化連續光譜**：將標題誘因簡化為 `0`/`1`，忽略了正常吸引注意與惡意誇大之間的灰色地帶。
5. **人為 50:50 類別平衡**：資料集正負比為 1:1，與真實新聞流中的低盛行率（Base Rate）不同，上線時不能直接依賴未校準機率與 Accuracy。

### Phase 1：資料盤點、EDA 與偏差診斷（Data Audit & EDA）
- **步驟 1.1 — 基礎品質盤點**：驗證 `clickbait_data.csv` 共 32,000 筆、2 欄、無缺失值、無完全重複列，`clickbait=0` 為 16,001 筆（50.003%）、`clickbait=1` 為 15,999 筆（49.997%）。
- **步驟 1.2 — 風格與捷徑訊號量化（Shortcut Audit）**：
  - 比較兩類別單字數（Label 0 平均 8.19 字 vs Label 1 平均 9.94 字）。
  - 量化格式與句型偏差（已實測確認之關鍵差異）：
    - **Title Case 比例**：Label 1 高達 **99.4%** vs Label 0 僅 **33.5%**。
    - **第二人稱（`you`/`your`）**：Label 1 **41.3%** vs Label 0 **0.3%**。
    - **數字開頭（Listicle）**：Label 1 **37.2%** vs Label 0 **2.6%**。
    - **標點符號異常**：Label 1 幾乎不含 `?`（0.3%）與 `!`（0.2%），且非 ASCII 字元為 **0.0%**。
    - **時間斷層**：Label 1 集中於 2015–2016 年，Label 0 分布於 2005–2012 年較多。
- **步驟 1.3 — 產出**：完成 `01_eda_and_bias_audit.ipynb`，記錄高頻 Uni-gram / Bi-gram 與上述偏差基線，作為 Phase 3 去偏處理依據。

---

### Phase 2：資料切分與防洩漏規範（Data Splitting & Leakage Prevention）
- **步驟 2.1 — 正規化重複檢核（防跨集合洩漏）**：
  - 在切分前對 `headline` 執行 `.lower().strip()` 檢查（實測有 1 筆正規化重複），確認無同一句型同時落入 Train 與 Test 的情況。
- **步驟 2.2 — 分層隔離切分**：
  - 使用 `StratifiedShuffleSplit` / `train_test_split(..., stratify=y, random_state=42)` 維持各集合 50:50 比例：
    - **訓練集（Train）**：70%（22,400 筆）— 用於詞彙表建立、5-Fold 交叉驗證與超參數調校。
    - **驗證集（Validation）**：15%（4,800 筆）— 用於模型選擇、消融實驗比較、機率校準與決策閾值調整。
    - **測試集（Test）**：15%（4,800 筆）— **完全隔離**，僅於 Phase 5 執行一次最終效能驗證。
- **防漏鐵律**：嚴禁在切分前對全體資料執行 `TfidfVectorizer.fit()` 或任何全域統計；所有轉換器必須置於 `sklearn.pipeline.Pipeline` 內。

---

### Phase 3：去偏前處理與特徵工程（Preprocessing & Feature Engineering）
針對 Phase 1 發現的格式與專有名詞捷徑風險，設計以下管線與對照實驗：

- **步驟 3.1 — 強制去偏文字清理**：
  - **強制全面轉小寫（`lowercase=True`）**：刻意剝除 Title Case 訊號，防止模型靠大小寫偷吃步。
  - **空白正規化**：去除多餘空白與換行符號。
  - **年份數字正規化（消融對照組）**：將 4 位數年份（如 `2015`、`2016`、`2008`）統一替換為 `<YEAR>` 權杖，驗證是否能消除年代斷層帶來的過擬合。
- **步驟 3.2 — 多層次特徵表示法**：
  - **詞級 TF-IDF（Word N-grams）**：`ngram_range=(1, 2)`、`sublinear_tf=True`、設定 `min_df=3~5` 過濾罕見人名與拼寫變體。
  - **字元級 TF-IDF（Character N-grams，應對 OOV 風險）**：以 `FeatureUnion` 結合 `analyzer='char_wb', ngram_range=(3, 5)`，提升對新詞彙、詞綴變體與輕微改寫的容錯力。
  - **結構統計特徵（謹慎使用）**：僅保留「字數」、「是否數字開頭」、「是否含第二人稱」，**排除**標點計數作為強規則（因本資料集 `?`/`!` 已被清洗失真）。
- **步驟 3.3 — 消融實驗（Ablation Study）**：
  - 在驗證集上比較「保留大小寫 vs 全面小寫」、「保留原年份 vs `<YEAR>` 遮罩」之差異，確保模型效能來自語意與句法而非排版漏洞。

---

### Phase 4：模型訓練、調參與機率校準（Modeling, Tuning & Calibration）
- **步驟 4.1 — Baseline 模型**：
  - `Pipeline([tfidf, LogisticRegression(max_iter=1000, C=1.0)])` 與 `MultinomialNB`，確認基準 F1 $\ge 0.90$。
- **步驟 4.2 — 多模型迭代比較**：
  - **線性邊界強化**：`LinearSVC` / `SGDClassifier`（搭配 L2 正則化抑制特定專有名詞過大權重）。
  - **非線性樹模型**：`LightGBM`（結合 TruncatedSVD 降維特徵與統計特徵）。
  - **語意表徵對照組（選用）**：微調輕量 Transformer（如 `DistilBERT` / `MiniLM`），評估其對 OOV 新詞彙與「刻意避開 `you`/數字」之對抗性改寫標題的召回率增益。
- **步驟 4.3 — 交叉驗證超參數調校**：
  - 於訓練集執行 5-Fold Stratified CV（`GridSearchCV` / `RandomizedSearchCV`），調校 `min_df`、`max_features`、`ngram_range` 與正則化係數 `C` / `alpha`。
- **步驟 4.4 — 機率校準與閾值最佳化（應對 Base Rate 差異）**：
  - 對線性或樹模型套用 `CalibratedClassifierCV`（Platt Scaling / Isotonic Regression），確保輸出機率具校準意義。
  - 於驗證集繪製 **Precision-Recall 曲線**，依據上線場景（如寧可漏抓不可誤殺）調整決策閾值，不盲目沿用預設 `0.5`。

---

### Phase 5：模型評估、可解釋性與錯誤分析（Evaluation & Error Analysis）
- **步驟 5.1 — 隔離測試集最終評估**：
  - 輸出完整 **混淆矩陣（Confusion Matrix）**、Accuracy、Precision、Recall、F1-Score、ROC-AUC、**PR-AUC** 與 Log Loss，並實測單筆推論延遲（須 $< 20\text{ ms}$）。
- **步驟 5.2 — 模型可解釋性審查（Explainability Audit）**：
  - 匯出 `LogisticRegression` / `LinearSVC` 權重最高的前 30 個正負向特徵詞，人工檢查是否有年份（`2015`）或單一明星/品牌名稱主導決策；若發現異常捷徑，退回 Phase 3 加強正則化或停用詞過濾。
- **步驟 5.3 — 分層錯誤分析（Sliced Error Analysis）**：
  - 針對高風險子群體進行切片檢視：
    1. **含數字的正常新聞**（如 `"1700 runners still unaccounted for..."`）之誤殺率（FP）。
    2. **不含 `you` 與非數字開頭的標題黨**之漏抓率（FN）。
    3. **極短標題（$\le 4$ 字）**之分類穩定度。
- **步驟 5.4 — 外部近期資料盲測（Out-of-Time Validation）**：
  - 收集少量 2024–2026 年真實英文新聞與社群標題（含現代標點 `?`、`!` 與新詞）進行外部盲測，量化領域偏移（Domain Shift）造成的效能落差。

---

### Phase 6：模型封裝、部署規劃與風險控管（Packaging & Deployment）
- **步驟 6.1 — 端到端管線封裝**：將前處理、特徵提取與已校準分類器打包為單一 `.joblib` 檔，透過 `src/predict.py` 提供 CLI 與函式推論介面。
- **步驟 6.2 — Human-in-the-Loop 分級決策（降低誤殺風險）**：
  - **高信心標題黨（$P \ge 0.85$）**：標記或降權處理。
  - **灰色邊界區間（$0.40 \le P < 0.85$）**：送交人工複審或僅作為輔助訊號，嚴禁直接自動下架正當創作者內容。
- **步驟 6.3 — 適用邊界聲明**：明確限制本模型僅適用於**英文短標題**輔助篩選，禁止未經微調直接套用於中文或其他語言平台。

---

### Phase 7：上線監控與持續學習（Monitoring & Retraining）
- **步驟 7.1 — 概念漂移監控**：定期追蹤線上輸入標題的 OOV 比例、平均字數與輸出機率分布漂移（PSI / KL 散度）。
- **步驟 7.2 — 主動學習與週期重訓**：收集邊界區間與人工申訴之誤判樣本（特別是現代標點與新興網路用語），定期人工標註並併入訓練集執行重訓。
