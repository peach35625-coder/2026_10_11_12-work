## 3. 資料規劃（Data Strategy）

### 3.1 資料來源與規格
- **資料來源**：`[資料庫 / CSV 檔案 / 公開資料集 / API]`
- **預計資料量**：`[例如：共 50,000 筆樣本，25 個欄位]`
- **資料授權與隱私**：確認是否包含個人敏感資訊（PII），必要時進行去識別化（Anonymization）。

### 3.2 資料切分策略（Data Splitting）
為避免資料洩漏（Data Leakage）並確保類別比例一致，採用分層抽樣（Stratified Sampling）：
- **訓練集（Train Set）**：70%（搭配 5-Fold Stratified Cross-Validation 進行調參與驗證）
- **驗證集（Validation Set）**：15%（用於模型選擇與早停 Early Stopping）
- **測試集（Test Set）**：15%（完全隔離，僅於最終階段進行一次效能評估）

> **注意**：若資料具有時間順序性（Time-series），須改採時間切分（Time-based Split），避免未來資料洩漏至訓練集。

## 4. 探索性資料分析與前處理（EDA & Preprocessing）

### 4.1 探索性資料分析（EDA）檢核項目
- 目標變數分布檢查（確認是否存在類別不平衡 Class Imbalance）
- 缺失值（Missing Values）比例與分布型態
- 異常值（Outliers）與資料型態錯誤檢查
- 特徵間相關性（Correlation Matrix / VIF）與特徵對目標的區分度

### 4.2 資料前處理與特徵工程管線（Pipeline）
所有轉換器（Scaler, Encoder, Imputer）僅能使用 **訓練集** `fit()`，再對驗證集與測試集進行 `transform()`：

1. **缺失值處理**：
   - 數值型：中位數 / 平均數補值，或搭配缺失指示欄位（Missing Indicator）
   - 類別型：眾數補值或獨立設為 `"Unknown"` 類別
2. **類別特徵編碼**：
   - 低基數無序類別：One-Hot Encoding
   - 有序類別：Ordinal Encoding
   - 高基數類別：Target Encoding / Frequency Encoding
3. **數值特徵縮放**：
   - 針對距離敏感或線性模型（Logistic Regression, SVM, KNN, MLP）：使用 `StandardScaler` 或 `RobustScaler`
   - 針對樹狀模型（Random Forest, XGBoost, LightGBM）：視需求保留原始尺度
4. **類別不平衡處理（若適用）**：
   - 調整類別權重（`class_weight="balanced"` / `scale_pos_weight`）
   - 訓練集內部重採樣（如 SMOTE 過採樣或 Random Under-sampling）
   - 調整分類決策閾值（Threshold Tuning）

## 5. 模型選擇與訓練策略（Modeling & Training）

### 5.1 候選模型清單
採用「由簡入繁」的實驗策略：

| 階段 | 模型名稱 | 選用理由 |
| :--- | :--- | :--- |
| **Baseline** | Dummy Classifier / Logistic Regression | 建立效能下限、確認特徵線性可分性與可解釋性 |
| **傳統整合樹模型** | Random Forest Classifier | 抗雜訊能力強、對離群值較不敏感、可輸出特徵重要性 |
| **梯度提升樹** | LightGBM / XGBoost / CatBoost | 表格資料（Tabular Data）分類任務主力，準確率高且支援類別不平衡權重 |
| **其他候選** | Support Vector Machine (SVM) / MLP | 視資料維度與非線性邊界複雜度補充比較 |

### 5.2 超參數調校（Hyperparameter Tuning）
- 使用 `GridSearchCV`、`RandomizedSearchCV` 或 `Optuna`（貝葉斯最佳化）進行參數搜尋。
- 固定隨機種子（`random_state=42`）以確保實驗可重現性（Reproducibility）。

## 6. 模型評估指標（Evaluation Metrics）

不應僅依賴準確率（Accuracy），特別是在類別不平衡的情境下，需綜合評估以下指標：

- **混淆矩陣（Confusion Matrix）**：檢視 TP、FP、TN、FN 分布，分析誤報（False Positive）與漏報（False Negative）的業務代價。
- **Precision（精確率） & Recall（召回率）**：依據業務需求權衡（例如詐欺偵測重視 Recall，垃圾郵件過濾重視 Precision）。
- **F1-Score（Macro / Weighted）**：Precision 與 Recall 的調和平均數。
- **ROC-AUC & PR-AUC**：評估模型在不同閾值下的整體排序與區分能力（極度不平衡資料優先參考 PR-AUC）。
- **模型可解釋性（Explainability）**：使用 Feature Importance、SHAP（SHapley Additive exPlanations）解釋單筆與全域預測依據。

## 9. 風險評估與應對策略（Risks & Mitigation）

| 潛在風險 | 影響程度 | 應對策略 |
| :--- | :---: | :--- |
| **資料洩漏（Data Leakage）** | 高 | 嚴格使用 `sklearn.pipeline.Pipeline`，確保所有統計量與縮放僅在訓練集計算；檢查是否誤用未來特徵。 |
| **嚴重類別不平衡** | 高 | 採用 Stratified K-Fold、調整 `class_weight`、使用 PR-AUC 與 F1-Score 評估，並調整分類閾值。 |
| **模型過擬合（Overfitting）** | 中 | 限制樹深度、加入正則化（L1/L2）、使用交叉驗證監控訓練與驗證分數落差。 |
| **資料品質不佳或缺失過多** | 中 | 於 EDA 階段即早盤點，與資料提供方確認欄位定義，必要時剔除低品質特徵。 |

## 10. 後續部署與維護規劃（Deployment & Monitoring）
- **模型封裝**：使用 `joblib` 連同前處理 `Pipeline` 一起匯出，確保推論時輸入格式一致。
- **監控指標**：上線後定期追蹤輸入特徵分布偏移（Data Drift）與預測類別比例變化（Prediction Drift），並設定定期重新訓練（Retraining）機制。
